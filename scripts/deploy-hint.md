# Деплой TenderCheck на tendercheck.pro

TenderCheck — статический сайт. После сборки (`scripts/build.sh`) всё нужное лежит в папке **`dist/`**:
`index.html`, `tendercheck.js`, `styles.css`, `favicon.svg`, а также служебные файлы `CNAME` (GitHub Pages)
и `_headers` (Netlify, Cloudflare Pages). Сервер, база данных и переменные окружения не нужны.

Если у вас готовый архив `tendercheck-pro.zip` с папкой `dist/`, собирать ничего не требуется:
распакуйте его и загрузите содержимое `dist/` на хостинг.

## 1. Выберите хостинг

Любой из четырёх вариантов бесплатен для проекта такого размера.

### GitHub Pages

1. Создайте репозиторий и загрузите в его корень **содержимое** папки `dist/` (не саму папку).
   Файл `CNAME` с доменом `tendercheck.pro` уже лежит в `dist/`.
2. Репозиторий → **Settings → Pages** → Source: *Deploy from a branch*, ветка `main`, папка `/ (root)`.
3. В поле **Custom domain** введите `tendercheck.pro` и сохраните.
4. Когда DNS обновится (шаг 2 ниже), включите **Enforce HTTPS**.

### Netlify

1. **Add new site → Deploy manually** и перетащите папку `dist/` в окно браузера.
2. **Domain management → Add a domain** → `tendercheck.pro`.
3. Netlify покажет, какие DNS-записи создать у регистратора, — используйте именно их.

### Cloudflare Pages

1. **Workers & Pages → Create → Pages → Upload assets**, загрузите папку `dist/`.
2. Вкладка **Custom domains → Set up a custom domain** → `tendercheck.pro`.
3. Если DNS домена уже на Cloudflare, записи будут созданы автоматически.

### Vercel

1. Установите CLI (`npm i -g vercel`) и выполните в папке `dist/` команду `vercel --prod`
   (на вопросе о фреймворке выберите *Other*), либо загрузите папку через веб-интерфейс.
2. **Settings → Domains → Add** → `tendercheck.pro`, затем создайте записи, которые покажет Vercel.

## 2. Привяжите домен tendercheck.pro

Записи создаются в панели DNS у регистратора домена (или у хостинга, если вы передали ему DNS).

| Хостинг | Для `tendercheck.pro` | Для `www.tendercheck.pro` |
|---|---|---|
| GitHub Pages | четыре записи **A**: `185.199.108.153`, `185.199.109.153`, `185.199.110.153`, `185.199.111.153` | **CNAME** на `<ваш-логин>.github.io` |
| Netlify, Cloudflare Pages, Vercel | значения из панели хостинга (A, ALIAS/ANAME или CNAME — зависит от регистратора) | **CNAME** на адрес, который указан в панели хостинга |

Заодно удалите старые записи A/AAAA для этого имени, если они остались от прежнего хостинга.

## 3. Дождитесь HTTPS

- DNS обновляется от нескольких минут до 24 часов; проверить можно командой `dig tendercheck.pro +short`.
- Сертификат выпускается хостингом автоматически (Let's Encrypt или собственный центр). Ничего покупать не нужно.
- После выпуска включите принудительный HTTPS (на GitHub Pages — флажок **Enforce HTTPS**, на остальных хостингах он включён по умолчанию).

## 4. Проверьте результат

1. Откройте `https://tendercheck.pro` — должна появиться главная страница с тремя уровнями.
2. Пройдите одну заявку и обновите страницу: прогресс и лучший результат сохраняются в localStorage.
3. Откройте вкладки «Глоссарий» и «О проекте», проверьте сайт на смартфоне.

## Обновление

Измените исходники или `data/scenarios.json`, выполните `scripts/build.sh` и заново загрузите содержимое `dist/`
(на GitHub Pages — сделайте commit и push). Домен и сертификат повторно настраивать не нужно.

## Если что-то не работает

- **Белый экран:** откройте консоль браузера (F12). Чаще всего на хостинг загрузили саму папку `dist` вместо её
  содержимого, и `index.html` оказался не в корне сайта.
- **Страница открывается по http, но не по https:** сертификат ещё не выпущен, подождите и проверьте DNS-записи.
- **Старая версия после обновления:** обновите страницу с очисткой кэша (Ctrl+F5); файлы кэшируются на час.
- **Прогресс пропал:** localStorage привязан к домену. Прогресс, накопленный на `localhost` или на адресе хостинга
  (`*.github.io`, `*.netlify.app`), не переносится на `tendercheck.pro`.
